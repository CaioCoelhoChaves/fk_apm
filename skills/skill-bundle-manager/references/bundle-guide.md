# APM Bundle Authoring & Lifecycle Guide

This reference explains how to author, configure, lock, and maintain APM skill bundles in the `fk_apm` repository.

---

## 1. What is an APM Bundle?

An APM bundle is a meta-package that groups multiple related skills together. When consumer projects (e.g. `fk_booster`, client apps, packages) install a bundle, APM automatically resolves and deploys all bundled skills in a single command, avoiding repetitive manual installations.

Existing examples in `fk_apm`:
- `default`: Essential utility skills (`skill-creator`, `skill-bundle-manager`).
- `flutter`: All Flutter development skills (`flutter-widgets`, `flutter-navigation`, `flutter-testing`, `flutter-accessibility`, `flutter-internationalization`).

---

## 2. Directory Layout of a Bundle

Every bundle is stored in its own subfolder under `bundles/`:

```text
bundles/<bundle-name>/
├── apm.yml           # Required: Bundle manifest declaring dependencies
├── apm.lock.yaml     # Required: Pinned dependency lockfile generated by 'apm lock'
└── apm_modules/      # Cache directory created by APM (ignored by .gitignore)
```

---

## 3. Authoring `apm.yml` for a Bundle

Create `bundles/<bundle-name>/apm.yml` following this standard:

```yaml
name: bundle-name
version: 0.1.0
description: Clear summary of the skills bundled together and target use cases
author: Caio Coelho Chaves
license: MIT

dependencies:
  apm:
    - ../../skills/first-skill-name
    - ../../skills/second-skill-name
  mcp: []
```

### Critical Rules:
1. `name`: Must match the directory name `bundles/<bundle-name>` exactly.
2. `dependencies.apm`: Must use relative paths pointing to the skills in `skills/` using `../../skills/<skill-name>`.
3. `version`: Semantic version, typically initialized at `0.1.0`.

---

## 4. Generating the Lockfile (`apm.lock.yaml`)

APM bundles **must** have an accompanying `apm.lock.yaml` committed to version control. This ensures reproducible installs in consumer projects.

To generate or refresh the lockfile:

```bash
# Navigate to bundle directory and run apm lock
cd bundles/<bundle-name>
apm lock
cd ../..
```

*(In PowerShell):*
```powershell
Set-Location bundles/<bundle-name>
apm lock
Set-Location ../..
```

Verify that `bundles/<bundle-name>/apm.lock.yaml` is generated and contains entries for all referenced skills.

---

## 5. Registering the Bundle in Root `apm.yml`

Open the root `apm.yml` file and add the bundle under `marketplace.packages`:

```yaml
marketplace:
  packages:
    # Existing packages...
    - name: bundle-name
      description: Clear summary of the bundle
      source: ./bundles/bundle-name
      version: 0.1.0
```

---

## 6. Updating Documentation & Verification

1. **Update `README.md`**: Add the bundle to the `### Available Bundles` table (see [references/readme-sync-guide.md](readme-sync-guide.md)).
2. **Offline verification**: Run `apm marketplace check --offline`.
3. **Rebuild marketplace**: Run `apm pack`.
4. **Audit**: Run `apm audit`.
